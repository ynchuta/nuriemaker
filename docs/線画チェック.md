# 線画チェック（線画化を直したときの確かめ方）

線画化の処理（`src/lineart.ts`）を直したら、「本当に良くなったか」「別の絵で悪くなっていないか」を
**同じ画像・同じ設定で、変更前と変更後を並べて** 確かめます。そのための道具です。

## 使い方

```sh
npm run linecheck                    # 変更前 = origin/main、変更後 = 今の作業中のコード
npm run linecheck -- --base HEAD~1   # 変更前を好きなコミットにする
npm run linecheck -- --base none     # 比べずに今の版だけ
npm run linecheck -- --only hair     # 名前に hair を含む画像だけ
npm run linecheck -- --strict        # 数字が悪くなったら失敗にする
```

結果は `linecheck-output/` に出ます。`index.html` をブラウザで開くと一覧で見られます。

- 比較画像（`お手本の名前__設定.png`）: 左から **元画像 ／ 変更前 ／ 変更後 ／ 差分 ／ 正解の線**
  - 差分: 灰 = どちらにもある線、**赤 = 消えた線**、**青 = 増えた線**
  - 正解の線: お手本画像のときだけ。本来あるべき線
- `full/` … 変換結果を等倍で保存したもの（拡大して細部を見るとき）
- `summary.md` … 数字の表

### GitHub で（PR ごとに自動）

`src/lineart.ts` などを変えた PR では、GitHub Actions の「線画チェック（比較画像）」が自動で動きます。

- 実行ページの **Summary** に数字の表（改善 ◎ ／ 悪化 ⚠）
- 同じページ下の **Artifacts → linecheck** をダウンロードして `index.html` を開くと比較画像

## しくみ

- アプリと**同じ線画化コード**（`src/lineart.ts` の `computeEdgeMaps` と `renderLineArt`）をそのまま Node で動かします。
  変更前の版は `git show` で取り出して同じように動かします。アプリのコードはテストのために変えていません。
- 画像の前処理もアプリに合わせています（長辺 1600px にそろえる、小さい画像は 4 倍まで拡大、透明部分は白）。
  この数値は `src/main.ts` から読み取るので、アプリ側で変えても自動でついてきます。
- 違いが 1 つだけあります: 画像の拡大縮小は、ブラウザではなく画像ライブラリ（sharp、Lanczos 法）で行います。
  ブラウザとはぼかし方がわずかに違うので、線の位置が 1px ずれる程度の差は出ることがあります。
- 設定は「3歳向け」「5歳向け」「8歳向け」と「太さ 6・細かさ 10」（実際によく使われた設定）の 4 つ。いずれも「線を中心でなぞり直す」オン。

## テスト画像

### お手本画像（リポジトリに入っている、`tools/linecheck/scenes.ts`）

実際にうまくいかなかった絵と同じ「つまずきポイント」を持つ絵を、図形で描いたものです。
形が分かっているので「正解の線」も作れ、数字で採点できます。

| 名前 | 再現している失敗 | 見るところ |
|---|---|---|
| thick-outline | 太い黒い輪郭線のキャラ（低解像度） | 輪郭が二重線（白抜き）にならない／体の暗い影や灰色の背景が線にならない／円盤のすき間が黒く埋まらない |
| hair-highlight | 暗い髪にツヤが帯のように並ぶ、眼鏡の顔 | ツヤとツヤの間が黒い塊にならない／目・眼鏡・口が残る／背景もようや頬のぼかしが線にならない |
| small-faces | 赤い背景の集合絵（小さい顔・低解像度・JPEG） | 小さい顔の目と口が残る／背景のもようがゴミにならない／顔の影が線にならない |
| shading | グラデーション・ぼんやりした影・肌のムラ | 影やムラがガサガサの線にならない／輪郭線とベルトが残る |

### 手元の画像（`test-images/private/`、Git には入らない）

実際のアニメ・ゲームの絵は著作権があり、このリポジトリは公開されているので入れられません。
手元で確かめたい絵は `test-images/private/` に置くと一緒に変換されます（正解の線がないので、数字は「黒い塊」だけ）。
よしひろさんが送ってくれた失敗例 3 枚は、プロジェクトのファイル「nuriemaker/テスト画像」に置いてあります。

## 数字の意味

長辺 1600px の画像で測ります。

| 数字 | 意味 | 良い向き |
|---|---|---|
| 見つかり率（輪郭線、目・口 など） | 正解の線のうち、変換結果の線がそばにある割合。目や口が消えると下がる | 高いほど良い |
| 余計な線・二重線 | 変換結果の線の中心のうち、正解の線から離れているものの割合。背景ノイズ、影のガサガサ線、二重線（輪郭の内側と外側の 2 本）があると上がる | 低いほど良い |
| 黒い塊 | 黒いところのうち、幅 18px（A4 に印刷して約 3mm）を超える「塗りつぶし」になった部分の割合。ツヤの間が黒く埋まると上がる | 低いほど良い |
| 黒の割合 | 画像全体のうち黒いところの割合（参考） | ― |

「そば」「離れている」の目安は 8px（A4 に印刷して約 1.3mm）。
変更前と比べて 2 ポイント以上動いたら、表で ◎ 改善 ／ ⚠ 悪化 と出ます。
数字は目で見る代わりではなく、**見落としを防ぐための目安**です。最後は必ず比較画像を目で見てください。

## 目で見るチェック観点

塗り絵として使えるかを、子どもが塗る立場で見ます。比較画像の「変更後」で確かめてください。

1. **二重線になっていない** … 太い輪郭線が、内側と外側の 2 本の線（白抜き）になっていない
2. **背景ノイズがない** … 背景のもよう・グラデーション・JPEG のモヤが、細かいゴミや線になっていない
3. **目・口・眉が残る** … 小さい顔でも目と口が分かる。眼鏡のふちが途切れていない
4. **陰影がガサガサ線にならない** … ぼんやりした影や肌のムラが、ギザギザの短い線の集まりになっていない
5. **黒い塊がない** … 髪のツヤの間、細かい部分のすき間が黒く塗りつぶされていない（塗る場所がなくなる）
6. **線がつながっている** … 塗る場所を区切る線が途中で切れていない（切れていると塗り分けにくい）
7. **線の太さがそろっている** … 同じ設定なら、場所によって線の太さが極端に変わらない
8. **細かすぎない** … 年齢向けの設定で、小さい子が塗れないほど細かい区切りになっていない
9. **他の絵で悪くなっていない** … 直したかった絵だけでなく、すべてのお手本・手元の画像で、差分に大きな赤（消えた線）や青（増えた線）が出ていないか

## 線画化を直す人へのお願い

- PR を出す前に `npm run linecheck` を実行し、`linecheck-output/index.html` を一通り見る
- PR の説明には、直したい絵の比較画像（変更前・変更後）と、Summary の表の結果（⚠ 悪化があればその理由）を書く
- 新しい失敗例が見つかったら、同じつまずきポイントを持つお手本を `tools/linecheck/scenes.ts` に足す
